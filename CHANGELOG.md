# Changelog

## Unreleased

- **Fill keys match hyphenated labels.** `email` now finds "E-mail address" (a key equal to a run of the label's words written together); two equally plausible fields are still refused as ambiguous.
- **Round-5 fixes.** A date typed into a bootstrap-datepicker box was verified and then submitted empty: the widget learns the text only from a `keyup` and rewrote the box when it closed. Fills now send one harmless `keyup` (found by reproducing on selenium.dev's web-form; fixture `picker`). A heading's ref now reads that heading's whole section (`snapshot ref=eN`), `wait_for` accepts `ms` for a plain pause, and the docs note that Bing may ignore pagination for headless sessions.
- **Round-4 live trial fixes.** `form_submit` re-reads the fields it verified just before clicking and reports any the page cleared or rewrote in between (`CHANGED BEFORE SUBMIT`), because a date picker had been reported "verified" and then submitted empty. Deltas use the same size budget as their baseline (a long page's tail no longer looks "removed"), `observe: none` still records a baseline, and a 404 says what to do next.
- **Round-3 live trial fixes.** Clicks that only change the hash or query of the same page (anchors, Bing "Page 2") now return a delta instead of the whole page; `back` at the start of a tab's history (including `tabs new`) says so instead of landing on `about:blank`; deltas ignore separator-only text (`|`) churn; empty image-only duplicates of a link are listed once; a result-less DuckDuckGo page is reported as a block with the "use another source" advice; unnamed verification pages are named by host.
- **Round-2 live trial fixes.** `back` with no earlier page says so (popup tabs start empty) instead of dumping the page; pages whose wrapper has a click handler (single-page apps such as rtings.com) are no longer collapsed into one `clickable`; deltas after `navigate` have a baseline instead of reprinting the page; footers collapse only with 5+ links and mention hidden fields (no more `0 links omitted` on cards); 429 reads "rate limited", binary files are not called PDFs, a stale ref no longer says "page script error", and the relevance warning is skipped on challenge pages.
- **Search-engine UX pass (first end-user trial).** Search-result links now show the real destination instead of a truncated tracking redirect (Bing `/ck/a`, Google `/url`, DuckDuckGo `/l/`, Yahoo `/RU=`). Bot-block pages that have no widget (Brave "Captcha", Startpage "Access Temporarily Suspended", "Access denied", `/sorry/`) now produce the `CHALLENGE:` hand-off, which also tells the agent to use another source. Navigation errors explain themselves (DNS, certificate, HTTP error status, download/abort, refused/reset/timeout). Interactive snapshots say that page text is omitted.
- **Search-engine bot walls are detected.** DuckDuckGo's "bots use DuckDuckGo too" page (a form with only a Submit button) was returned as an ordinary page, so an agent would try to click through it. It now produces the same `CHALLENGE:` hand-off as other walls. Found by driving real MCP sessions against Google, DuckDuckGo and Bing. Fixture: `captcha_search_wall`.
- **Clearer error when a `--profile-dir` is already in use.** Chrome allows one process per profile, so a second `ostler serve --profile-dir X` exited with "browser exited before DevTools was ready". The message now names the profile and says to use one profile per server.
- **Upload confinement.** File fields are refused unless `--upload-dir DIR` allows the directory. Paths are resolved first, so `..` and symlinks cannot escape, and the browser receives the resolved path. **Breaking:** uploads used to accept any local path.
- **No DevTools port.** Chrome now talks to Ostler over `--remote-debugging-pipe` instead of an unauthenticated localhost WebSocket port that any local user could drive. Verified: no listening socket in the browser's process tree (one appears with `OSTLER_CDP_TRANSPORT=ws`, kept for debugging). Chrome also exits on its own when Ostler dies. Large messages work (a 121 MB screenshot message in 3.6 s).
- **Port-aware allowlist and private-network blocking.** `--allow-domain example.com:8443` (or `https://example.com:8443`, `[::1]:8080`) pins a port; an entry without a port still allows every port. `--block-private-networks` refuses loopback, RFC 1918, link-local/cloud metadata, CGNAT, ULA, mapped IPv6, `.local`/`.internal` names and names that resolve to them when no allowlist is set. On by default for `ostler a2a` (`--allow-private-networks` opts out), off for `serve`.
- **`confirm()` and `prompt()` are dismissed** instead of auto-accepted (`--accept-dialogs` restores the old behaviour). The agent is told which dialogs appeared and what was done. **Behaviour change.**
- **`form_fill` no longer prints page labels on its trusted verdict line.** Found by a new test that puts attacker text in a title, body, label, alert, validation message and hidden element and checks every tool output: labels now sit below the verdict inside the wrapper, while our own trailing `Ready:` hints stay outside it.
- **Allowlist now covers every request type, WebSockets and popups.** A 20-minute soak with a canary server on a non-allowlisted origin found that `--allow-domain` let `<img>`, stylesheets, WebSockets and a `window.open` popup reach it (the interception listed only six resource types, and a popup is attached after its first request has gone out). Interception now holds every request, and Chrome starts with `--host-resolver-rules` so every other host is unresolvable browser-wide. After the fix the canary receives nothing across 12 exfiltration channels, by hostname and by IP literal.
- **Hidden text is not shown to the agent.** Text with computed opacity 0, a font size under 2px, far off-screen, or the same colour as a solid background is omitted from snapshots and labels, and the snapshot says how many runs were left out. Controls are never dropped (a native checkbox at opacity 0 under a custom one still works), and screen-reader-only text is kept. Fixture: `concealed.html`.
- **Titles, URLs, dialog text and the `look` legend are inside the untrusted wrapper.** They were bounded and defanged but sat on trusted lines, so a page title could carry an instruction. 
- **`screenshot` no longer stalls 30 s when a popup took the front.** Chrome produces no frame for a tab that is not in front, so a full-page capture of a tall page waited out the timeout. The tab is brought to front first (also fixes `look`).
- **Form inspection scales better on large forms.** Error-cue detection scanned the whole grandparent for every field; it now looks a bounded distance ahead. 1,000 flat fields: inspect 513 to 257 ms; 5,000: 13.6 s to 6.8 s. Fill on very large forms (thousands of fields) is still slow because every key re-reads the form.
- **Verification walls are detected and handed to a person** ([ADR-0009](docs/adr/0009-challenges-are-handed-off.md)). reCAPTCHA / hCaptcha / Turnstile widgets and "verify you are human" interstitials now produce a `CHALLENGE:` line on page-affecting tool results, a new `wait_for_human` tool (needs `--headed`), and an `input-required` A2A task. Ostler does not solve or bypass them. Invisible badges and ordinary pages that mention verification are not flagged. Fixtures: `captcha_widget`, `captcha_interstitial`, `captcha_badge_only`.
- **Actions are never replayed after a navigation.** `eval` retries across navigations, which re-ran the whole script on whichever page came next (a script that posts once ran 8 times in a test). Runtime calls that change the page (`jsClick`, `apply`, `setNative`, `comboPick`, `pickDate`, `finish`) now use `eval_once` and report that the page changed; a click that replaces its own page counts as a successful click. Closes the last open P0 item from the external review.
- **Learning loop, ranked in Qdrant** ([ADR-0008](docs/adr/0008-learning-loop.md)). Playbooks now keep wins and losses per form and per field mapping and are patched by every fill outcome. Mappings that fail more than they win are dropped. After a redesign, mappings transfer from a similar form on the same site (`via: similar_form`). Candidates are ranked inside Qdrant by a score-boosting formula over similarity, smoothed win rate and recency. New: `ostler memory skills`, `ostler memory prune --days N`, `form_inspect` hints for transferable knowledge, new payload indexes (`host`, `labels_norm`, `verified_ts`, `wins`, `losses`) created on existing collections too, and `tests/learning_eval.rs` (1 to 8 correct of 10 fillable fields on redesigned forms, 0 wrong, on both the in-memory store and real Qdrant 1.20).
- **Verification fixes (external review, 2026-10-31).** `datetime-local` fields were always graded `Exact`; they are now normalized and compared like dates and times, so a page that rewrites or clears the value fails. Combobox verification no longer treats a substring as equivalent ("United States" vs "United States Minor Outlying Islands" is a mismatch), and the in-page picker now only picks an exact (normalized) option label, listing the available options otherwise. `form_fill` reports `unsettled` (a count) when the page was still busy after a settle timed out. New fixtures `datetime.html` and `combobox_diverge.html` with e2e tests.
- **Snapshot quality.** Long text is split into several lines with an explicit `… [N more chars cut]` marker instead of silent cuts at 300 chars; refs keep their numbers past a truncated view; footers collapse to one line in interactive and delta views (`snapshot ref=eN` expands); delta now applies across same-path URLs and ignores ref renumbering; unknown-ref errors say what to do.
- **Searching the web.** `navigate` warns when a Google/Bing/DuckDuckGo/Brave/Yahoo/Ecosia/Startpage results page shows too few of the query's words (the engine may be degrading results). New "Searching the web" docs: what to expect per engine, `--headed` + `--profile-dir`, `wait_for_human`, and search APIs for discovery. Docs and `doctor` now say to reconnect the MCP client after rebuilding.
- **Navigation and click honesty.** `navigate` reports the HTTP status (`Navigated (HTTP 404)`) and puts it, with a plain-language reason, in navigation errors; PDFs/non-HTML documents, downloads and redirects to a sign-in page are labelled; `click` now ends with a `Result:` line (navigated, popup opened as tab tN, page updated, or no visible change).

- **`look` tool: where to click.** A viewport screenshot with every clickable element boxed and labelled by its ref (green submits, blue inputs, purple links, red has an error), plus a legend of what each does. Boxes come from DOM geometry; elements under a modal or sticky bar are left out and counted. Overlay is removed afterwards.
- **Visual error cues.** Fields marked invalid only by colour (red border/outline/glow, red message text with no ARIA or class) and floating toasts/banners are now reported as field and page errors. Leftover errors on fields just filled are tagged as possibly stale.
Fixes from the [design review](docs/REVIEW-2026-10.md) (status table there), plus three features.

- **Renamed Waymarker to Ostler** (crates `ostler-*`, binary `ostler`, env vars `OSTLER_*`, config `~/.config/ostler/config.toml`). Move an existing `~/.config/waymarker` directory to `~/.config/ostler` and rename `WAYMARKER_*` variables.
- **Tool output is terse by default.** Verified fields are named once instead of one line each, form names no longer include the form's whole text, and fingerprints, timings and repeated page titles are gone. About 30% less text on a four-call form flow (1.5 KB to 1.0 KB). `--verbose` (or `verbose = true` in the config) restores the detail.
- **Tabs and shared context.** New `tabs` tool (list, new, switch, close). All tabs share one browser context, so cookies carry across; popups open as tabs under the same policy; new `context` tool is a notepad every tab and later call can read, kept across browser restarts.
- **A2A.** `ostler a2a` serves Agent2Agent v1.0 (JSON-RPC, SSE streaming): Agent Card, `SendMessage`, `SendStreamingMessage`, `GetTask`, `ListTasks`, `CancelTask`, `SubscribeToTask`. Tasks move to `input-required` for missing values, rejected input and submit confirmation. Per-conversation browsers; loopback by default; bearer token to listen elsewhere; `Origin`/`Host` checks. Verified with the official A2A Python SDK. See [docs/A2A.md](docs/A2A.md).
- **Wrong-fill prevention:** keys resolve against every visible field once, so an ambiguous key cannot win by elimination; forms re-mounted by a framework are followed; keys can no longer be silently dropped, and `FillReport::ok()` counts unmatched keys.
- **Memory:** learned values never overwrite facts you saved; playbooks persist only exact (playbook/autocomplete) matches; semantic matches need a margin over the runner-up and never apply to labels about other people; fixed the playbook key being cut at the first space.
- **Safety:** the allowlist is enforced at the network layer; `--require-confirm-submit` blocks all non-GET requests outside a confirmed submit; the untrusted-content wrapper cannot be closed by page text; secrets are masked in snapshots and notes and scrubbed from stored episodes.
- **Reliability:** a crashed Chrome is relaunched and the agent is told; closed connections fail immediately; larger WebSocket frames; `panic = "abort"` removed.
- **MSRV** is now Rust 1.89. (An earlier entry said 1.82; that was never true for the locked dependencies, which need edition 2024. CI now checks it.)

- **New:** `ostler setup <claude|codex|cursor|vscode|json> [--apply] [-- serve flags]` prints client config with the binary's absolute path; `--apply` runs `claude mcp add`. `doctor` now points to it.
- **New:** `ostler init` (interactive or flag-driven; saves Qdrant URL/key, tenant, defaults to `~/.config/ostler/config.toml` with `0600` permissions and tests the connection) and `ostler config show|path|set|unset`. Precedence: flag, environment variable, config file, default. Qdrant Cloud URLs get `:6333` added. Key is masked in `config show`.
- **Docs:** README rewritten (quickstart, real tool output, measured-vs-modelled labelling, known gaps), `docs/TROUBLESHOOTING.md`, and the [design review](docs/REVIEW-2026-10.md).

## 0.2.0

Found by writing harder fixtures first; each fix has a regression test.

- **Fixed:** custom ARIA radio groups (`role=radio` inside `role=radiogroup`) were reported with no options and, on re-read, as a multi-select. They are now a single `radio` field with options from the widgets' labels.
- **New:** calendar date pickers on read-only inputs. When a text field is read-only and the value is a date, the engine opens the popup, navigates months and clicks the day (`pickDate`). Fails with a reason, not silently, when no popup or navigation is found.
- **Tests:** 4 new e2e tests (custom ARIA widgets and contenteditable, conditional fields revealed mid-fill, hidden-branch validation message surfaced, calendar picker) and a hostile-input test that sends malformed arguments to every MCP tool. 73 tests total.
- **Efficiency:** release profile with thin LTO, one codegen unit, stripped symbols. `ostler` binary 9.3 MiB to 6.0 MiB (same machine, same commit apart from the profile). Task latency was not re-measured and is not claimed to change.
- Fixtures: `aria`, `conditional`, `datepicker` (14 total).

Known limits of the new pieces: the date picker is heuristic (month header text plus prev/next controls plus day cells) and has only been tried on one fixture; year-only or dropdown-based pickers are not handled.
